# Statements the community-scope scan lets through, one per line:
#
#   path:routine   # why every statement in this routine is platform-level
#   path           # why this whole file is platform-level
#   path/          # why this whole tree is platform-level
#
# An entry is a statement that is platform-level BY DESIGN: one that cannot be
# scoped because the community is what it is looking up, or one that answers
# across every community. A statement that merely lacks a predicate is a
# finding, not an entry. The scan runs again on every check, so a new statement
# in the same file or routine is still judged on its own.
#
# The delivery layer was scanned with an empty allowlist first: every statement
# in `apps/` already scopes the tables it names (a `where`/`join` predicate or
# the column list of an insert), so no entry below covers it.

# Operator tools run outside a community context: the operator names the
# community on the command line and the job then works inside it. Import also
# has to find v1 rows by their old keys before it knows the community.
tools/

# Key rotation re-seals every live share link under a new key, across every
# community, selected by `key_id`; the community comes from each row.
modules/share/store.nim:rotateKeys

# An invite token or email hash is presented before any community context
# exists; the row is read first and the community it carries is the result.
modules/community/infrastructure/invite.nim:lookup
modules/community/infrastructure/invite.nim:acceptPendingForEmail
modules/community/infrastructure/invite.nim:accept

# Account deletion asks which communities a user touched before choosing one;
# every branch is keyed by that user, and the writes that follow are scoped.
modules/account/infrastructure/lifecycle_store.nim:communitiesOf

# BE-06: SQL and the process-global `application.db` are not allowed in the
# delivery layer. Each entry below is one handler routine the extraction has
# not moved yet; the reason names why it has no module home. The scan is per
# routine: a statement in a routine without an entry is a finding, and a new
# routine needs its own reviewed entry. An entry exempts the whole routine, so
# remove it once the statements move rather than growing it in place.
#
# Format:
#
#   apps/path/file.nim:routine   # why this routine is still a handler
#   apps/path/file.nim           # why the whole file has no application home
#
# Remove an entry when its routine moves to `modules/<name>/application/`.
#
# Wave 5 (2026-11-10) took this file from 77 to 8 entries. The pool is named
# once below; the seven routines left are listed with the reason each has no
# module target yet.

# The pool itself, named once. Every handler takes its `Db` from here and holds
# no SQL of its own, so it is not allowlisted. This is the documented exception
# the rule asks for.
apps/api/src/app.nim:database

# The readiness probe reads the migration ledger, the required relations and
# the cutover row. It is a process-level check of "is this process pointed at a

# hand a store.
apps/api/src/app.nim:readyz

# Account doors that run before any community context exists. The service would

apps/api/src/app.nim:requestJoin
